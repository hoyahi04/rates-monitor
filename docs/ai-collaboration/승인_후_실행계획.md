# 중앙 AI 작업공간의 승인 후 실행계획

작성일: 2026년 10월 30일. **현재 외부 자원 생성, 유료 서비스 가입, OAuth 앱 등록, 자격증명 발급·저장, 실제 사용자 파일 업로드는 수행하지 않았다.** 아래 이름은 생성된 자원명이 아니라 검토 가능한 계획값이다. 계정·리전·예산을 확정하고 승인받은 다음 단계부터 실행한다.

## 승인할 기본 구성

작업 원본은 버전 관리가 켜진 S3 버킷 하나에 둔다. Claude Code, Codex, ChatGPT, Gemini CLI 또는 API가 하나의 HTTPS 주소를 사용한다. 파일 편집은 클라우드 작업자에서 하고 PC 동기화 폴더를 만들지 않는다. 수정안의 원본 반영은 초기에는 사용자 승인 화면에서만 수행한다. 일반 Gemini 웹 앱의 임의 MCP 연결은 검증되지 않았으므로 기본 연결 경로에서 제외하고, Gemini CLI/API를 사용한다.

| 항목 | 계획값 | 승인·확인할 범위 |
|---|---|---|
| 운영 클라우드 계정 | `<사용자가 선택한 AWS 계정>` | 새 계정 생성이나 결제수단 등록은 별도 허용이 있어야 수행 |
| 운영 리전 | `<선택 리전>` | 서울 리전을 우선 견적 후보로 삼되 실제 단가·서비스 지원 확인 후 확정 |
| 작업 원본 버킷 | `ai-workspace-<account-suffix>-<region>` | 이름 가용성 확인 후 생성, 비공개·버전 관리·기본 암호화·공개 접근 차단 |
| 프로젝트 | `personal-workspace` | 초기에는 샘플 프로젝트 하나, 실제 파일은 지정된 것만 가져옴 |
| 원본 객체 경로 | `projects/personal-workspace/objects/` | 신규 불변 버전만 저장 |
| 현재 상태 | `projects/personal-workspace/workspace.json` | 조건부 갱신만 허용, 현재 리비전·확정 영수증 관리 |
| 작업·후보 경로 | `projects/personal-workspace/jobs/`, `proposals/`, `previews/` | 본문·미리보기 역시 비공개로 취급 |
| 게이트웨이 서비스 이름 | `ai-workspace-gateway` | AWS Lambda + API Gateway HTTP API를 1차 구현 후보로 선택. 짧은 JSON 응답과 비동기 작업 조회를 사용하며 네 MCP 클라이언트 호환성 시험 후 확정 |
| 접속 주소 | `https://<배포 시 발급받은 호스트>/mcp` | 실제 발급 주소를 사용. 새 유료 도메인 구입은 포함하지 않음 |
| 문서 작업자 | `ai-workspace-document-worker` | ECS/Fargate 작업 단위 컨테이너를 1차 후보로 선택. 작업별 격리·임시 저장 정리, 매크로 실행과 임의 외부 연결 기본 금지 |
| 작업 대기열 | `ai-workspace-jobs` | SQS를 후보로 선택. 작업 ID만 전달하고 원본 파일·확정 상태는 S3에 유지 |
| OAuth 앱 표시명 | `Personal AI Workspace` | Cognito를 1차 로그인 후보로 검토. MCP 메타데이터·클라이언트 등록 흐름의 호환성을 먼저 시험하고 허용 사용자·리다이렉트·범위를 확정한 뒤 등록 |
| 백업 대상 | `<별도 백업 계정>/ai-workspace-backup-<suffix>` | 독립 계정·비공개 버킷에 복구 전용 시점 복사. 운영 AI의 수정 경로에서 제외 |
| 초기 인프라 예산 목표 | USD 20/월 이내 | 보장 견적 아님. 선택 리전의 기본 서비스·로그·백업 견적이 이를 넘으면 배포 전 조정 |
| AI API·렌더·OCR 비용 | 별도 사용량 상한 | 기존 구독의 API 포함을 가정하지 않음. API 사용이 필요한 경로만 활성화 |

S3 버전 관리와 조건부 쓰기는 공식 지원 기능이다. 기본적으로 꺼진 버전 관리를 실제 설정에서 켜고, 리전별 단가로 최종 견적을 산출해야 한다. ([버전 관리](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html), [조건부 쓰기](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html), [S3 요금](https://aws.amazon.com/s3/pricing/))

위 호스팅 제품은 구현·견적을 진행할 구체적인 **후보 조합**이며, 배포 가능한 설정 파일이나 검증된 OAuth 통합을 이미 제공한다는 의미는 아니다. 컨테이너 이미지 저장, 네트워크 경로, 인증, 비밀 저장, 로그 비용도 포함해 산정한다. 특히 상시 네트워크 구성 비용 때문에 월 USD 20 목표를 넘는다면 사용량에 맞는 호스팅 대안을 비교한 뒤 승인할 구성을 다시 제시한다. 긴 문서 편집을 Lambda 요청 안에서 끝내는 구조는 채택하지 않는다.

## 부여할 권한과 저장할 인증 정보

게이트웨이와 작업자는 클라우드 역할의 임시 자격증명을 사용한다. PC나 AI 프롬프트에 S3 장기 키를 넣지 않는다. OAuth 설정상 필요한 비밀만 선택한 클라우드 비밀 관리 서비스에 저장한다. **어떤 키도 승인 전에는 발급하거나 저장하지 않는다.**

| 역할·연결 | 허용 범위 | 제외 범위 |
|---|---|---|
| AI 조회·제안 | 해당 프로젝트 목록·원본 읽기, 신규 후보·작업 생성 | 원본 확정, 삭제, 버킷 설정, 다른 프로젝트 |
| 문서 작업자 | 해당 작업의 입력 리비전 읽기·출력 키 쓰기 | manifest 갱신, 다른 작업 조회, 관리자 API, 무제한 외부 접속 |
| 사용자 확정 서비스 | 승인된 후보 읽기·현재 manifest 조건부 갱신 | 과거 버전 삭제, 계정·버킷 정책 변경 |
| 백업 작업 | 운영 스냅샷 읽기·백업 신규 쓰기 | 운영 쓰기, 기존 백업 삭제 |
| 보존기간 정리 작업 | 승인한 기간과 참조 검사에 따른 제한적 정리 | AI의 일반 도구로 노출하지 않음 |
| 각 AI의 OAuth 연결 | `workspace:read`, `proposal:create`, `job:read` 등 필요한 범위 | 사용자 승인 자체를 대신하는 범위 |

IAM 권한 문서는 프로젝트 prefix와 객체 역할을 반영해 먼저 준비하고, 실제 허용·거절 시험을 통과한 뒤 운영 데이터를 넣는다. 임시 자격증명·최소 권한·S3 공개 접근 차단은 AWS 권장 방식이다. OAuth는 MCP의 보호된 리소스와 대상 서버 검증을 구현한다. ([IAM 권장사항](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html), [S3 보안](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html), [MCP 인증](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization))

**GitHub App 설치는 S3 기본안에 필수인 승인 항목이 아니다.** 사용자가 코드 PR 흐름을 별도로 원하면 선택한 비공개 저장소 하나에 `Contents read/write`, `Pull requests read/write`, 필요한 메타데이터 읽기만 부여하는 추가 계획을 적용한다. Contents 쓰기는 경로 제한 토큰이 아니며 비공개 보호 브랜치의 요금제 조건도 확인한다. GitHub를 시스템 소스 보관에만 쓸 경우에는 작업 원본 저장소로 혼용하지 않는다. ([GitHub App 권한](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app), [보호 브랜치](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches))

## 실제 실행 순서와 남길 결과

| 순서 | 실행 내용 | 완료 결과·검증 |
|---|---|---|
| 1 | 계정·리전·OAuth 공급자·호스팅 후보·예산을 확정하고 세부 견적 작성 | 실제 계정·제품·리전·월 비용 가정이 채워진 배포 명세. 아직 내용이 미정인 서비스는 생성하지 않음 |
| 2 | S3 어댑터, 게이트웨이, 영속 멱등 처리, 승인 화면을 구현하고 로컬 계약 시험 | 불변 객체·manifest CAS·재시도·경로·권한 테스트 결과 |
| 3 | 승인된 원본 버킷·역할·인증 앱·게이트웨이를 생성 및 연결 | 실제 엔드포인트, 자원 목록, 역할별 허용·거절 결과. 비밀 값은 보고서에 포함하지 않음 |
| 4 | 민감하지 않은 샘플 텍스트로 원격 읽기·제안·사용자 확정·재조회 | 파일 ID, 이전·이후 리비전, SHA-256, 요청 ID |
| 5 | 두 동시 수정과 응답 유실을 재현 | 한쪽 충돌 보존, 중복 확정 방지, 실패 후 상태 복구 기록 |
| 6 | Claude Code·Codex·ChatGPT·Gemini CLI/API를 순서대로 연결 | 각 계정 로그인, 도구 목록, 동일 파일 읽기·후보 생성·최종 재조회 결과 |
| 7 | 일반 DOCX·XLSX·PPTX·PDF 작업자를 구현하고 대표 샘플 검증 | 전후 미리보기·구조 검사·수식 재계산 여부·지원하지 않는 기능 목록 |
| 8 | 독립 백업과 복구 절차 설정, 시험 복구 | 복구 manifest·파일 해시 일치, 실제 RPO/RTO 측정 |
| 9 | 기존 PC 종료 후 다른 PC에서 이어받기 | 동기화 없이 같은 파일과 최신 작업 기록으로 후속 작업 성공 |
| 10 | 사용자가 지정한 실제 파일을 단계적으로 가져오기 | 원본·파생물 구분, 수용 테스트 결과, 운영 사용 안내 |

코드 구현을 끝내기 전에 버킷만 만들어 연결 완료라고 보고하지 않는다. 네 AI 중 하나의 계정에 필요한 커스텀 연결이 막혀 있다면 그 계정의 제한과 대체 경로를 기록한다. 다른 클라이언트가 성공했다고 전부 성공한 것으로 처리하지 않는다. 일반 문서 샘플이 통과했다고 매크로·전자서명·암호 파일까지 지원한다고 확대하지 않는다.

## 보존·복구·중단 기준

초기 보존안은 후보 14일, 확정 버전 90일, 일별 백업 30일, 본문 없는 감사기록 90일이다. 현재 원본과 보존 중인 스냅샷이 참조하는 객체는 기간만으로 삭제하지 않는다. 복구 목표는 RPO 24시간·RTO 4시간이며, 월 1회 시험 복원으로 실제 달성 여부를 확인한다. 백업 계정 구성이 아직 없으면 독립 백업을 준비하기 전 운영 완료로 표시하지 않는다.

시험 실패 시에는 새 수정안 접수를 멈추고 이미 확정된 원본을 읽기 전용으로 유지하는 방식부터 적용한다. 실패한 후보와 로그를 보존하고 권한·도구·렌더링 문제를 수정한 뒤 해당 시험을 다시 수행한다. 자원 정리나 서비스 종료는 별도 확인 후 진행하고, 백업과 원본을 즉시 영구 삭제하는 처리를 기본 종료 절차로 넣지 않는다.

비용은 사용량 알림과 함께 작업 수·파일 크기·실행 시간 제한으로 관리한다. 예산 목표에 가까워지면 새 고비용 작업의 접수를 제한하고 알린다. 이미 발생한 저장·로그·요청 요금을 정확히 특정 금액에서 멈출 수 있다고 약속하지 않는다. 예상 비용이 승인 범위를 넘는 구성, 새로운 유료 가입, 권한 확대, 대규모 파일 반출은 실행 전에 구체적인 변경 내역을 다시 확인한다.

## 지금 검토할 수 있는 것과 아직 없는 것

지금 제공하는 것은 설계서, 이 실행계획, `cloud-ai-hub`의 부분 구현과 **오프라인 시험 15개 통과 결과**다. 부분 구현은 메모리상의 불변 객체·스냅샷 확정 코어와 GitHub 텍스트 PR 제안 코드다. 실제 클라우드 서버 주소, 배포된 버킷, 저장된 자격증명, 네 AI의 실제 연결 성공 기록, Office/PDF 편집 품질 증거는 아직 없다. 다음 승인은 위 범위를 실제 계정과 예산으로 구체화해 단계적으로 구축하는 데 대한 것이며, 기존 로컬 예제를 완성된 서비스로 간주하는 승인이 아니다.
