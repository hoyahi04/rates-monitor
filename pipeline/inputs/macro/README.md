# 매크로 섹션 공통 틀 (담당자 5명 공유)

각자 폴더 하나를 맡고, 아래 **같은 형식**으로 만든다. 형식이 같아야 매크로 페이지에서 합쳐지고,
판정 요약 띠가 각 섹션의 맨 윗줄만 모아 만들어진다.

## 섹션 구성

1. **판정 한 줄** — 이번 달 점수 (−1 / 0 / +1)와 근거 한 문장
2. **차트 2~3개** — 지표 추이와 신호 계산 과정이 보이게
3. **전략 시사점** — 이 점수가 어느 커브 뷰에 들어가는지

## 담당자별 산출물

| # | 폴더 | 담당 | 점수 +1의 뜻 | 들어가는 커브 뷰 |
|---|---|---|---|---|
| 1 | `01_policy_path/` | 정책 경로 | 시장이 연준보다 인하를 덜 가격 | 수준, 기울기 |
| 2 | `02_growth_jobs/` | 성장·고용 | 경기 둔화 | 수준 |
| 3 | `03_inflation/` | 인플레이션 | 물가 둔화 | 수준, 기울기 |
| 4 | `04_supply_tp/` | 수급·기간 프리미엄 | 장기물 공급 부담 증가 | 기울기 |
| 5 | `05_liquidity_vol/` | 유동성·변동성 | 변동성 안정 | 곡률 |

## 각 폴더에 넣을 것

```
0X_name/
├── fetch_data.py     FRED 등에서 데이터 수집 → data.js + csv
├── analyze.py        신호 점수·백테스트 계산 → signals.js + signals_monthly.csv
├── index.html        섹션 페이지 (판정 → 차트 → 시사점 → 백테스트 근거)
├── data.js           웹페이지용
├── *.csv             분석용
└── notes.md          지표 의미·전달 경로·신호 정의·백테스트 결과
```

`03_inflation/`이 끝까지 구현된 예시다. 세 파일(`fetch_data.py`, `analyze.py`, `index.html`)을 복사해서 지표만 바꿔 쓰면 된다.
`signals_monthly.csv`의 점수 열이 팀 점수표에 들어갈 값이다.

## 통합 점수표

`python3 scoreboard.py`(이 폴더에서)가 다섯 섹션의 점수 열을 읽어 `scoreboard.csv`와 `scoreboard.js`를 만든다.
한 줄이 한 달이고, 신호 5개 → 커브 뷰 3개(수준·기울기·곡률) → 포지션 4개 순서로 열이 놓인다.
섹션 점수를 새로 받으려면 각 폴더에서 `python3 fetch_data.py`를 먼저 돌린다.

- Fly z-score 룩백은 팀 확정 전이라 3년을 기본으로 쓰고(`fly_z_3y`), 1년 값(`fly_z_1y`)도 함께 적어 둔다.
- 브레이크(5번이 −1이면 포지션 절반)는 제안 단계라 `brake`, `size_multiplier` 열로 따로 두었다. 규칙대로의 듀레이션은 `duration_active_yr`, 브레이크를 적용한 값은 `duration_active_yr_with_brake`다.

## 신호를 정의할 때 지킬 것

- **수준이 아니라 서프라이즈로**: 이미 가격에 반영된 정보로는 초과수익이 나지 않는다.
  지표는 `실제치 − 컨센서스`, 정책은 `선물 내재 경로의 변화`로 잡는다.
- **그 시점에 공개돼 있던 값만**: 발표 시차를 반영한다 (예: 10월 말 결정에 10월 Core PCE를 쓰면 안 됨).
- **문턱값은 백테스트 전에 확정**: 결과를 보고 고치면 과최적화다.
- **예측형인지 반응형인지 밝힐 것**: 다음 달 커브를 설명하면 예측형(포지션 근거),
  발표 당일만 움직이면 반응형(시나리오·위험관리용).

## 백테스트 공통 질문

1. 이 신호가 1 표준편차 움직였을 때 **발표 당일** 2y·10y·30y는 평균 몇 bp 움직였나?
2. 신호 점수가 +1인 달의 **다음 달** 커브는 예상대로 움직였나? (hit rate)
3. 국면별(인상기 / 동결기 / 인하기)로 결과가 다른가?

기간: 2015년 1월 ~ 현재. 2015~2020에서 규칙을 정하고 2021년 이후는 검증만 한다.
