# Rates Desk — 채권 데스크 대시보드

`대시보드.pdf`의 구성(홈 + 메뉴 6개 + 공통 요소 3개)을 공개 자료만으로 만든 화면입니다.
2페이지 버전(`3. dashboard/`)은 그대로 두었고, 이 폴더는 그 자료를 읽어 쓰는 새 버전입니다.

> **이 저장소에서의 위치**: 화면은 `desk/`, 자료를 만드는 스크립트는 `pipeline/desk/`에 있습니다 (아래 본문의 `4. desk/pipeline`은 `pipeline/desk`로 읽으면 됩니다).
> `build_data.py`가 읽는 `2. portfolio`·`1. macro`는 `pipeline/inputs/curve`·`pipeline/inputs/macro`, `3. dashboard/portfolio.js`는 `pipeline/model/portfolio.js`입니다.
> 모형 포트폴리오(`portfolio.js`, `backtest.py`)는 `pipeline/model/`에 있습니다. 베타(`/beta/`)는 `.github/workflows/pages.yml`이
> 평일 매일(한국 시간 화~토 08:30)과 배포할 때마다 자료를 새로 받아 올립니다. 받은 자료는 저장소에 커밋하지 않으므로,
> 이 폴더의 `data/desk_data.js`와 확정본(`/`)은 마지막으로 커밋된 시점의 자료입니다.

## 여는 법

`index.html`(버전 1)이나 `v2.html`(버전 2)을 더블클릭합니다. 인터넷 연결이나 서버가 필요 없습니다.

| 버전 | 파일 | 모양 |
|---|---|---|
| 1 | `index.html` | 왼쪽 메뉴, 테두리 있는 카드, 히트맵 표 중심 |
| 2 | `v2.html` | 왼쪽 글자 메뉴(아이콘 없음), 흰 바탕에 회색 상자와 파란 강조 (`3. dashboard/combined.html`의 느낌) |

두 버전은 자료와 코드가 같고 모양만 다릅니다. 버전 2는 `assets/theme-v2.css` 한 파일을 더 읽을 뿐이라,
화면 내용을 고치면 둘 다 바뀌고 매일 자동 갱신도 둘 다 됩니다. 화면 안의 "v2 보기" / "v1 보기"로 같은 화면끼리 오갑니다.

주소 끝에 붙일 수 있는 것:

| 붙이는 말 | 하는 일 |
|---|---|
| `#/market` | 그 화면으로 바로 감 (`home`, `market`, `macro`, `flows`, `rv`, `credit`, `book`) |
| `?theme=dark` | 어두운 화면 (`light`는 밝은 화면. 없으면 기기 설정) |
| `?region=KR&mat=long&asset=credit&period=3Y` | 필터를 정해서 열기 |
| `?bond=91282CRX1` | 그 CUSIP의 채권 상세를 연 채로 시작 |
| `?panel=news` | 뉴스를 연 채로 시작 |

## 화면 머리말: 결론 → 설명 → 근거

화면마다 맨 위 세 줄은 같은 순서입니다. 큰 글자는 **결론**(그래서 어떻다는 것인가), 그 아래는 **설명 한 줄**(숫자로 본 사실),
작은 글자는 **근거**(결론을 낸 숫자와 기준, 출처)입니다. 결론은 아래 규칙으로 자료에서 만들어지므로 자료가 바뀌면 같이 바뀝니다.
문턱값은 화면을 읽기 쉽게 하려고 정한 임시 기준이고, 매매 규칙이 아닙니다.

| 화면 | 결론이 답하는 것 | 재료와 기준 |
|---|---|---|
| 홈 | 이번 주 금리 움직임이 포트폴리오에 유리했나 | 한 주 동안의 벤치마크 대비 초과수익(±0.5bp 안이면 "거의 같게"), 10년 금리 방향, 액티브 듀레이션의 부호 |
| 시장 모니터 | 이번 주가 어떤 장이었고 움직임이 컸나 | 2년·10년 금리 변화의 방향(평균 ±3bp), 주가 한 주 등락(±3%부터 함께 봄), 10년 금리 변화 ÷ 최근 1년 주간 변화의 표준편차 (2배 이상 "컸다", 0.6배 미만 "작았다") |
| 매크로·정책 | 매크로 신호가 금리 어느 쪽을 가리키나 | 점수표의 지금 기준 점수 가운데 정책·성장·물가 (+1이 금리 하락 쪽)와 그 합 |
| 수급·펀딩 | 수급이 장기 금리에 어느 쪽이고 자금시장은 어떤가 | 수급 점수, 최근 입찰 3건의 응찰률(2010년 이후 하위 25% 약함·상위 25% 강함), SOFR − IORB (경보, 또는 3년 백분위 80 이상이면 "빠듯한 편") |
| RV·전략 | 눈에 띄게 싸거나 비싼 자리가 있나 | 스프레드 6개·버터플라이 6개 가운데 3년 z-score가 평균에서 가장 먼 것 (1 미만이면 "없음"), 그 자리의 3개월 캐리+롤다운 |
| 크레딧·소버린 | 신용 시장이 불안한가 | 하이일드 OAS의 3년 백분위 (80 이상 높음, 20 이하 낮음)와 한 달 변화 (±30bp) |
| 포트폴리오·리스크 | 듀레이션을 어느 쪽으로 얼마나 가져갔고 성과는 어떤가 | 액티브 듀레이션의 부호, 사전 추적오차 ÷ 위험예산 하단 (60% 미만 "소폭"), 정보비율 × √운용 연수 (절댓값 2 미만이면 "벤치마크와 사실상 같다") |

결론 문장은 `assets/views/*.js`의 "결론 한 줄" 부분에 있습니다.

## 용어

화면의 말은 국내 채권 운용 실무에서 쓰는 표현에 맞췄습니다.

| 영어 | 화면 표기 | | 영어 | 화면 표기 |
|---|---|---|---|---|
| performance attribution | 성과 분해 | | on-the-run | 지표물 |
| active duration | 액티브 듀레이션 | | reopening | 리오픈 |
| rich / cheap | 고평가 / 저평가 | | wings / leg | 윙 / 레그 |
| fitted curve | 적합 커브 | | in-sample / out-of-sample | 표본 내 / 표본 외 |
| carry / roll-down | 캐리 / 롤다운 | | max drawdown | 최대 낙폭 (MDD) |
| ex-ante / ex-post TE | 사전 / 사후 추적오차 | | clean / dirty price | 클린가격 / 더티가격 |
| risk budget | 위험예산 | | market value | 평가금액 |
| book | 포트폴리오 | | IORB | IORB (지급준비금 이자율) |

전략 이름(Duration, Curve Slope, Curve Curvature, Carry & Rolldown)과 메뉴 이름은 연구 계획과 `대시보드.pdf`의 표기를 그대로 둡니다.

## 다시 만들기

```
cd "4. desk/pipeline"
python3 fetch_extra.py     # 새 공개 자료 받기 (2분쯤)
python3 fetch_korea.py     # 한국 자료 (인증키가 있을 때만)
python3 build_data.py      # data/desk_data.js 만들기
```

표준 라이브러리만 씁니다. `build_data.py`는 다른 폴더가 만든 자료도 읽으므로, 전부 새로 받으려면 먼저
`2. portfolio/fetch_data.py`, `1. macro/0X_*/fetch_data.py`, `1. macro/scoreboard.py`, `3. dashboard/backtest.py`를 돌립니다.
GitHub Actions(`.github/workflows/pages.yml`)가 미국 장 마감 뒤(한국 시간으로 화~토 아침 8시 30분)에 이 순서대로 돌려 베타에 올립니다.

받기에 실패한 묶음은 지난번 값을 그대로 두고, 무엇이 실패했는지는 `desk_data.js`의 `meta.problems`에 적힙니다.

## 한국 자료 넣기

한국은행 ECOS는 인증키가 있어야 합니다.

1. https://ecos.bok.or.kr/api/ 에서 가입하고 인증키를 받습니다 (무료).
2. 이 폴더에 `.env` 파일을 만들고 `ECOS_API_KEY=받은키` 한 줄을 적습니다. `.env`는 `.gitignore`에 들어 있어 올라가지 않습니다.
3. `python3 fetch_korea.py && python3 build_data.py`를 돌립니다.
4. 자동 갱신에도 넣으려면 GitHub 저장소의 Settings → Secrets and variables → Actions에 `ECOS_API_KEY`라는 이름으로 키를 등록합니다.

키를 넣으면 채워지는 것: 국고채 1~50년 커브와 히트맵, 국고 3s10s, 미국−한국 10년 금리차, 한국은행 기준금리, 회사채 AA-·BBB- 스프레드, 금리차로 본 환헤지 비용 근사.
키 없이 요청 형식만 확인하려면 `python3 fetch_korea.py --check`.

한국 종목별 가격(금융투자협회 채권정보센터)은 아직 연결하지 않았습니다.

## 숫자를 읽을 때

- **색**: 빨강은 오름(+), 파랑은 내림(−)입니다. 손익은 이익이 빨강입니다. 매크로 화면의 서프라이즈와 월별 지표 표만 "금리를 올리는 쪽"이 빨강입니다.
- **내 포트폴리오**는 실제 종목이 아니라 만기 구간마다 모형 국채 한 종목을 든 계산입니다 (`3. dashboard/backtest.py`). 거래비용은 0입니다.
- **종목 상대가치**(저평가·고평가)는 잔존만기가 비슷한 종목들로 만든 적합 커브와 비교한 금리 차이입니다. 쿠폰 차이에서 오는 금리 차이는 걸러내지 않았고, 재무부 종가는 시장 호가와 다를 수 있습니다.
- **캐리·롤다운**은 금리가 지금 그대로라는 가정의 3개월 값이고, 조달 금리는 SOFR입니다.
- **지표의 "예상"**은 시장 컨센서스가 아니라 직전 추세로 만든 대용치입니다.
- **시나리오와 스트레스**는 듀레이션만으로 계산한 근사입니다 (볼록성과 이자 제외).
- **국가 스코어카드의 "종합"**은 신용등급이 아니라 표 안의 아홉 나라끼리 견준 상대 점수입니다. 재정(정부부채), 경제(실업률), 시장(10년 금리 수준과 1년 변화)을 나라들 안의 순위로 0~100점으로 바꿔 같은 무게로 평균했고(모두 낮을수록 좋다고 봄), 60점 이상 양호 · 40점 미만 주의입니다.
- **종목 종가**는 다음 영업일에 공시되어 금리 기준일보다 하루 이를 수 있습니다. 표마다 기준일이 적혀 있습니다.

## 점검

```
python3 pipeline/desk/bondmath.py     # 채권 계산식 자체 점검 (저장소 루트에서)
node desk/assets/bondmath.js check            # 화면 쪽 계산이 파이썬과 같은 값을 내는지
```

화면은 주소 끝에 `?selftest=1`을 붙이면 차트에 마우스를 올리고, 표를 누르고, 필터를 한 바퀴 돌려 본 뒤
결과를 `<html data-selftest="...">`에 적습니다.

검증에 쓴 사실: 재무부 종가로 계산한 최근 발행물의 만기수익률이 재무부 par 금리와 0.3bp 안에서 맞습니다
(2년 4.623% 대 4.63%, 10년 4.920% 대 4.92%, 30년 5.310% 대 5.31%, 2026-11-20 기준).
